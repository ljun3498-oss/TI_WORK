## 🔧 技术架构

### 系统分层

```
┌─────────────────────────────────┐
│  WPF UI (MainWindow.xaml)       │  ← 用户界面
├─────────────────────────────────┤
│  C# Logic (MainWindow.xaml.cs)  │  ← 业务逻辑
├─────────────────────────────────┤
│  P/Invoke (MotionControlAPI.cs) │  ← C# ⟷ C 桥梁
├─────────────────────────────────┤
│  C Library (motion_control.dll) │  ← 核心算法
└─────────────────────────────────┘
```

### 双定时器设计

- **SimTimer (1ms/1000Hz)**: 高频控制循环
  - 轨迹规划更新（10ms分频）
  - 位置环控制（1ms）
  - 电机仿真
  
- **PlotTimer (50ms/20Hz)**: 低频UI更新
  - 图表刷新
  - 状态显示
  - 性能监控

### 关键技术

- **P/Invoke**: C# 调用原生 C DLL
- **Struct Marshalling**: 结构体内存映射
- **OxyPlot**: 高性能实时绘图
- **WPF MVVM**: 数据绑定和事件处理

## 🔍 调试技巧

### 1. 监视缓冲区健康
**正常状态**: 缓冲数量在 20-80 之间波动
**异常状态**: 
- 长时间接近0 → 轨迹生成太慢
- 长时间接近128 → 位置环太慢
- 溢出次数增加 → 生成过快
- 欠载次数增加 → 消耗过快

### 2. 观察跟随误差
**理想**: 跟随误差 < 10 counts
**调整**: 增大 Kp 减小跟随误差

### 3. 检查运行日志
所有操作都有时间戳记录，便于追溯问题

### 4. 调整仿真频率
- 低频（100Hz）: 降低CPU占用，观察宏观行为
- 高频（2000Hz）: 精细仿真，测试极限性能

## 🛠️ 常见问题解决

### Q1: DLL加载失败
**错误**: `DllNotFoundException: Unable to load DLL 'motion_control.dll'`

**解决**:
1. 确认 `motion_control.dll` 存在
2. 检查DLL是64位（与C#程序匹配）
3. 将DLL复制到 `bin\Debug\net6.0-windows\`

---

### Q2: 编译DLL失败
**错误**: `gcc: command not found`

**解决**:
1. 安装 MSYS2: https://www.msys2.org/
2. 在MSYS2终端运行: `pacman -S mingw-w64-x86_64-gcc`
3. 添加到PATH: `C:\msys64\mingw64\bin`
4. 重启命令提示符

---

### Q3: 图表不显示
**现象**: 窗口空白或图表无数据

**检查**:
1. 是否点击了 "使能轴"
2. 是否发送了运动命令
3. 查看日志是否有错误信息
4. 检查 NuGet 包是否正确还原

---

### Q4: 速度曲线不平滑
**现象**: 速度曲线有锯齿

**原因**: 这是正常的！梯形曲线本身是分段线性的。

**改进**: 如需S曲线，需修改C库的轨迹规划算法。
